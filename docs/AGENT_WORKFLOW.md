# Agent 工作流规范

> 适用于当前项目及以后新建的软件项目。
> 根目录 `AGENTS.md` 只保留简短引用和强制规则，详细规范见本文件。

## 区分：开发任务 vs 工具日常使用

### 开发任务
需要修改代码、规则、配置或文档时：
- 执行 Git 检查、分支、状态确认
- 运行测试验证
- 生成开发报告（`python tools/generate_step_report.py`）
- 提交并推送

### 工具日常使用
用户上传图片进行核算或校准时：
- **不检查 Git**
- **不创建分支**
- **不运行测试**
- **不生成开发报告**
- **不输出文件扫描和命令执行过程**
- 直接按 SKILL.md 中的交互模式执行

## 1. 开始任务

只读取：

1. 根目录及当前项目 `AGENTS.md`；
2. 上一阶段报告；
3. 当前任务文件；
4. 与任务直接相关的源码和测试。

除非确有必要，不扫描整个仓库、全部历史报告或已作废方案。

开始前只简要说明：

```text
风险等级：
阶段目标：
预计修改范围：
测试策略：
```

## 2. 开发粒度

- 一个阶段默认包含 **2～4 个紧密相关子任务**。
- 每个阶段完成一个可独立验收的模块，不把一个字段、小函数单独拆成完整阶段。
- 每个逻辑单元形成可回退 Commit；无关内容不得混入同一 Commit。
- 当前阶段连续完成，阶段结束后集中复审，减少反复复制粘贴。

## 3. 风险分级

- **低风险**：文档、文字、非关键展示。运行局部检查，可合并相邻修改。
- **中风险**：普通服务、UI、文件管理、导入导出。运行模块测试，阶段后集中复审。
- **高风险**：利润、物流、汇率、数据库迁移、历史数据、配置兼容。独立分支、边界测试、全量回归，未复审不得继续。

## 4. 测试节奏

```text
开发中：当前测试
子任务完成：相关模块测试
阶段完成：全量测试
里程碑完成：全量测试 + 关键人工流程
```

禁止删除测试、降低断言、把失败改成跳过或伪造通过结果。

## 5. 自动报告

每个有效步骤完成后运行固定报告脚本：

```text
python tools/generate_step_report.py
```

脚本负责 Git 状态、分支、Commit、修改文件和测试结果。
Agent 只补充：

- 实现内容；
- 关键设计；
- 真实风险；
- 遗留问题。

聊天窗口只输出摘要和报告路径，不重复粘贴完整报告。

## 6. Git 与交付

- 开始前确认工作区、分支和基线提交。
- 每个 Commit 必须单一、清晰、可回退。
- 不提交缓存、日志、真实数据库、密钥和临时输出。
- 不自动合并稳定分支，不强制推送。
- 阶段结束后确认工作区状态和推送状态。

## 7. 根目录 AGENTS.md

根目录保持精简，只保留：

- 仓库边界；
- Git 与数据安全底线；
- 测试底线；
- 报告脚本调用；
- 本文件路径。

项目业务规则放在项目级 `AGENTS.md`，具体步骤放在任务文件中，避免重复。

## 8. 完成反馈

只反馈：

```text
完成内容：
关键文件：
测试结果：
报告路径：
Commit：
推送状态：
真实风险/遗留问题：
```

核心原则：

> 中等粒度开发、风险分级验收、机械工作脚本化、阶段集中复审；节省额度不能以稳定性和数据安全为代价。
