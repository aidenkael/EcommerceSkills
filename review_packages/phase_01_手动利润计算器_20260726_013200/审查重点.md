# 审查重点 — phase_01

## 请审查者优先检查以下内容

### 1. 计算公式是否准确

**重点文件**：`calculation/logistics.py`、`calculation/profit.py`、`calculation/currency.py`

- 体积重 = 长×宽×高÷8000 是否正确？
- 计费重量 = max(实际重量, 体积重) 逻辑是否符合跨境物流行业惯例？
- 头程费用 = 计费重量×单价 是否正确？
- 建议售价反算公式 `总成本÷(1−利润率−推广比例)` 是否合理？
- 人民币↔美元换算方向是否正确？

### 2. 售价和利润率双向联动是否会循环

**重点文件**：`ui/product_page.py`（`_do_recalculate` 方法，约230—310行）

- `_last_modified` 追踪逻辑是否正确？
- `_programmatic` 标记是否能有效防止 trace 回调循环？
- 修改售价 → 更新利润率，再修改利润率 → 更新售价，两个方向互斥？
- USD 价格输入 → 转换 RMB → 触发 RMB trace → 会不会死循环？

### 3. SQLite 保存是否可靠

**重点文件**：`database/db_manager.py`

- 表结构是否包含所有必要字段？
- 首次保存快照逻辑：是否真的只保留第一份？
- 外键约束 `ON DELETE CASCADE` 能否正确级联删除快照？
- 配置表 `INSERT OR IGNORE` 默认值是否正确？
- 读回的数据是否与写入一致？（已有测试验证）

### 4. UI 和计算模块是否分离

- `calculation/` 是否包含任何 tkinter 引用？（**不应包含**）
- `ui/` 是否包含业务计算公式？（**只有调用，没有公式实现**）
- 如果未来换用 PyQt/web 界面，calculation 模块是否可以原样复用？
- database 模块是否独立于 UI？（**是**，只依赖 sqlite3）

### 5. 空字段是否会导致崩溃

**已验证**（59项测试全部通过），但建议审查以下边界：

- 只填长宽，不填高 → 体积重为 None → 界面应显示「数据不足」
- 售价为空 → 利润和利润率为「数据不足」
- 汇率为 0 → 换算结果为「数据不足」
- 利润率为 0 → 正常计算（利润为 0）

### 6. 当前结构是否方便以后接入图片识别

- `products` 表是否预留了 `image_path` 字段？（**是**）
- 是否有独立的图片管理模块？（**否，phase_02 开发**）
- 是否有 AI 接口层？（**否，按指令不开发**）
- UI 是否支持图片拖拽？（**否，phase_02 开发**）

建议：phase_02 新增 `images/` 模块时，只需：
1. 数据库增加 `image_path` 使用（已有字段）
2. 新增 `images/image_manager.py`
3. UI 增加图片上传组件
4. 不影响现有计算、数据库、配置模块

### 7. 代码质量问题

- 是否有硬编码的配置值？（汇率 7.2、头程 100 均已配置化 ✅）
- 是否有未使用的 import？
- 函数文档字符串是否完整？
- 异常处理是否充分？（`_safe_float` 捕获所有转换异常 ✅）

### 8. 数据安全

- 数据库文件路径是否安全（无注入风险）？（使用参数化查询 ✅）
- 是否有 SQL 注入风险？（全部使用 `?` 占位符 ✅）
- 是否有隐私数据泄漏？（无 API 密钥、无真实用户数据 ✅）
