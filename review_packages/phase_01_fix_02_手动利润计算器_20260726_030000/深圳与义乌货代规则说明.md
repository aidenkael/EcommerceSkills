# 深圳与义乌货代规则处理说明 — v0.1.2 (fix_02)

## 当前状态：未区分深圳与义乌

**Phase 01 不实现深圳/义乌的货代规则切换。** 当前全部物流费用统一使用以下单一模型：

| 参数 | 值 | 含义 |
|------|-----|------|
| 头程单价 | 100.00 元/kg（可配置） | 义乌→美国头程运输单价 |
| 固定服务费 | 6.00 元/单（可配置） | 操作处理费 |
| 默认尾程费用 | 40.00 元（可配置） | USPS 尾程配送 |

## 与基线的差异

根据用户历史记忆，原始物流模型为：
- 体积重除数：8000（与本阶段一致）
- 头程单价：100 元/kg（与本阶段一致）
- 固定服务费：36 元 → **已改为 6 元**（基线修正）
- 默认尾程配送费：0 元 → **已改为 40 元**（USPS 实际费率）

## 当前线路假设

本阶段默认假设：
- 供应商 → 义乌中转仓（用户手动输入国内运费）
- 义乌中转仓 → 美国（头程，按计费重量 × 单价计算）
- 美国尾程配送（USPS，默认 40 元）

## 深圳线路未实现

如果未来需要支持深圳线路，差异点可能包括：
- 国内运费不同（供应商 → 深圳 vs 供应商 → 义乌）
- 头程单价可能不同
- 尾程配送服务商可能不同

## 如何扩展为多线路

建议的分阶段实现方案（非本阶段范围）：

### Phase 03/04（后期）
1. 在设置中增加"发货仓"选项：义乌 / 深圳
2. 配置表扩展为按线路存储：
   ```sql
   CREATE TABLE route_config (
       route_name TEXT PRIMARY KEY,  -- 'yiwu' or 'shenzhen'
       head_haul_rate REAL,
       fixed_service_fee REAL,
       default_tail_haul REAL
   );
   ```
3. 商品表增加 `route` 字段
4. 计算时根据商品的 route 读取对应费率

### 当前可用的手动变通方案

用户可以通过以下方式手动模拟深圳线路：
1. 菜单 → 设置 → 修改头程单价和尾程费用为深圳线路的值
2. 新商品将使用修改后的费率
3. 历史商品保持保存时的费率（需点击「用当前费率重算」更新）

**限制**：不能同时保存义乌和深圳两套费率，切换线路需手动修改设置。

## 后续规则版本管理

当前 `rule_version = 1` 的规则集：
- 线路：义乌
- 体积重除数：8000
- 头程单价：100 元/kg
- 固定服务费：6 元
- 尾程默认：40 元

当增加深圳线路或修改规则时，`rule_version` 将递增，旧商品可通过快照中的 `rule_version` 追溯当时规则。
