7. 数据库版本和业务规则版本混为一体

## 四、数据库 schema 变化

### Schema v1 → v2

```sql
-- products: +freight_forwarder TEXT DEFAULT NULL
-- product_snapshots: +tail_haul_cost REAL, +volume_divisor INTEGER, +rule_snapshot TEXT
-- 新建 route_config 表 (forwarder PK, head_haul_rate, fixed_service_fee)
-- 新建 business_rule_version 表 (version PK, description, applied_at)
```

### 默认数据
```
route_config: shenzhen(80/10), yiwu(100/6)
business_rule_version: 2 (双货代规则)
schema_version: 2
```

### 迁移保护
- `_backup_db()`: 迁移前自动复制 .backup_v{N} 文件
- `BEGIN TRANSACTION / COMMIT / ROLLBACK`: 全事务保护
- `_add_column_if_missing()`: 安全补列（已有列跳过）
- 旧商品 freight_forwarder = NULL（不自动猜测货代）

## 五、物流规则版本变化

| 版本 | 说明 |
|------|------|
| v1 | 单线路：义乌 100元/kg + 6元 |
| **v2** | **双货代**：深圳 80元/kg + 10元 / 义乌 100元/kg + 6元; 体积重÷8000 不变; 尾程默认 40元 不变; 汇率单独管理 |

### 规则管理
- `business_rule_version` 表独立追踪业务规则版本
- `schema_version` 表仅追踪数据库结构版本
- 两者完全分开

## 十、潜在风险

1. 非数字/负数校验依赖 tk.Entry `bg` 色变化，某些 Windows 主题可能不显示
2. 旧商品 freight_forwarder=NULL 时显示"未知"，用户需手动选择货代后才能计算
3. 迁移备份文件会累积（每次迁移前生成 .backup_v{N}），需定期清理
