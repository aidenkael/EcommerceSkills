# AGENTS.md — 物流成本核算 Skill v2.1

## 项目目标
电商单件跨境物流头程成本核算 Skill。Codex 读取商品图片 → 输出 AI JSON → Python 确定性计算。

## 两种互斥模式

任何时候只允许一个有效模式：

| 模式 | 名称 | 说明 |
|------|------|------|
| 1 | 利润核算 | 识别商品 → 两档四方案头程 + 总成本与利润表 |
| 2 | 仅头程 | 识别商品 → 两档四方案头程表（不计算利润、不询问利润参数） |

**禁止同时执行两个模式。** 禁止在同一次图片核算中先输出头程表再自行追加校准分析。

## 仅头程模式定义

"仅头程"只排除尾程、商品总成本、利润率、活动预留和预计利润。

"仅头程"**必须完整展示**每个方案的：包装尺寸、包装后重量、计费重、纯头程、固定服务费、总头程。

```
纯头程 = 计费重 × 货代单价
总头程 = 纯头程 + 固定服务费
```

**纯头程不是最终头程成本。总头程才是用户比较两家货代时的最终头程成本。**

货代推荐必须按总头程比较，不得只按每公斤单价或纯头程比较。

强制规则：
- 不得出现"本表只看头程，所以不含固定服务费"之类解释
- 固定服务费属于头程成本组成部分，不能因为模式名为"仅头程"而移除
- 义乌与深圳的推荐结果必须比较：纯头程 + 各自固定服务费
- 禁止仅因为"深圳80元/kg低于义乌100元/kg"就直接推荐深圳

## 模式状态与默认参数

### 唯一状态来源

模式和默认参数的唯一状态来源是本地文件：

```
config/local_user_preferences.json
```

结构：

```json
{
  "active_mode": null,
  "exchange_rate": null,
  "tail_fee_usd": null,
  "target_profit_rate_percent": null,
  "activity_reserve_percent": null
}
```

- `active_mode`: `profit_accounting` / `head_only` / `null`
- `exchange_rate`: 1 USD 对应的 RMB 数值
- `tail_fee_usd`: 单件尾程 USD
- `target_profit_rate_percent`: 目标利润率百分数（如 20）
- `activity_reserve_percent`: 活动预留百分数（如 15）

**不得修改 `config/logistics_config.json` 来保存用户偏好。**

### 模式切换规则

模式只允许通过以下情况改变：
1. 用户明确选择模式
2. 用户明确说"切换到利润核算"
3. 用户明确说"切换到仅头程"
4. 用户明确回复模式编号 1 或 2，且当前正在等待模式选择

**以下内容不得改变模式：**
提交 Git、查看 Git 状态、修改文档、输出 Markdown/PDF/Excel、生成文件、解释代码、检查仓库、普通问答、翻译、总结、临时要求另一种展示格式、任何与核算模式无关的任务。

无关任务正常执行，但完成后：`active_mode` 保持不变、默认参数保持不变、下一张核算图片仍读取本地偏好文件。

### 首次使用

当用户上传需要核算的商品图片，且 `active_mode = null`，只回复：

```
请选择默认核算模式：

1. 利润核算
2. 仅头程

选择1时，请同时提供：汇率、尾程USD、目标利润率、活动预留。
示例：1，7.20，7，20%，15%
```

回复后停止，不提前识图、不运行脚本、不输出商品分析。

### 默认参数保存规则

- 用户首次提供后自动保存为本地默认值
- 后续所有利润核算直接读取，不重复询问
- 用户明确修改任意一项时，只更新该项，其余保持不变
- 除非用户明确说"本次、临时、不保存、不修改默认"，否则新参数自动覆盖默认值
- 仅头程模式不读取、不询问、不清空、不修改这些参数

## 区分：开发任务 vs 工具日常使用

### 开发任务
修改代码、规则、配置或文档 → 执行 Git 检查、测试、报告和提交流程。

### 工具日常使用
用户上传图片进行核算 → 不检查 Git、不创建分支、不运行测试、不生成开发报告、不输出文件扫描和命令执行过程。

日常核算不生成文件：
- 日常图片核算默认不保存 AI JSON
- 日常图片核算默认不生成 output/*.md
- 日常图片核算默认不生成过程文档
- 日常图片核算默认不修改 examples/
- 日常图片核算默认不提交 Git
- AI JSON 如程序运行必须使用内存数据或系统临时文件，用完后删除
- 只有用户明确要求"保存JSON""生成Markdown报告""加入正式示例"时，才允许生成对应文件
- 用户只是上传图片核算，不构成保存文件授权

禁止输出内部处理过程：
- 不显示"先保存偏好""开始商品识别""确认脚本处理""字段名不对""重新修正JSON""再次运行脚本""保存过程文档"等
- 正常情况下直接输出：一句商品信息 + 一个固定表格 + 一句推算
- 遇到真实阻断时，只说明用户需要补充什么，不输出排查过程

## 业务规则

- 物流公式和费率只从 `config/logistics_config.json` 读取，不写死任何数值。
- AI JSON 格式参照 `examples/socks_ai.json`，包装方案必须提供 normal 和 conservative 两档。
- Python 负责：证据仲裁、软品检查、重量修正、确定性头程计算。
- 软品展开尺寸不得作为包装尺寸；体积重 > AI 净重 ×3 时自动忽略。
- 用户可信净重使用净重 + 0.05kg；低可信重量不得进入可信流程。
- 1688 链接只保存，不访问网页。
- 参数修改必须显示原值和建议值并由用户确认。
- 保持实现简洁，只修改任务所需内容。
