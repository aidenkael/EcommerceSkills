# AGENTS.md — 物流成本核算 Skill v2.1

## 项目目标
电商单件跨境物流头程成本核算。Codex 读取商品图片 → 输出 AI JSON → Python 确定性计算。

## 任务分类

**开发任务：** 修改代码、规则、配置或文档 → 执行 Git 检查、必要验证和提交。

**日常核算：** 用户上传图片或要求计算 → 不检查 Git、不运行测试、不写报告、不生成文件。

## 模式（仅当前对话有效）

两种模式：1. 利润核算 / 2. 仅头程。

- 新对话第一次出现核算图片或请求时，必须询问模式。
- 用户选择后，当前对话后续图片沿用。
- 新对话不得读取上一个对话的模式作为默认。
- 模式不保存到 `local_user_preferences.json`。

## 四项参数（跨对话持久化）

仅持久化：`exchange_rate`、`tail_fee_usd`、`target_profit_rate_percent`、`activity_reserve_percent`。

保存于 `config/local_user_preferences.json`。用户修改任意一项时只更新该项。仅头程模式不读取这些参数参与输出，但不清空。

## 日常快速路径

```
确认当前SKU和数量
→ 一次图片理解
→ 选择一个最匹配的物理结构类型
→ 读取对应规则
→ 生成正常档与保守档
→ 运行一次Python确定性计算
→ 按固定Markdown格式输出
```

默认不得：扫描仓库、逐类比较全部规则、读取案例库、访问网页、执行Git、运行测试、保存AI JSON、生成Markdown/PDF/Excel、输出内部过程。

## 调用上限

每个商品默认最多：1次图片理解 + 1次结构规则匹配 + 1次Python计算。

仅异常检查命中时允许：重新生成包装方案1次 + 再运行Python计算1次。不得循环重试。

## 当前SKU优先

证据优先级：用户明确说明 > 当前高亮SKU/已选文字/数量 > 当前规格重量和尺寸 > validated案例 > 通用物理规则 > pending案例 > AI经验推测。

禁止用同页套包、其他颜色、宣传组合或历史套包覆盖当前单包。

## 通用物理包装原则

任何商品都必须先区分展示状态与运输状态，再判断刚性主体、可折部件、可拆附件、压缩、嵌套和局部保护；不得把展示总尺寸直接作为运输包装尺寸。

详细分类见 `SKILL.md` 和 `knowledge/physical_packaging_rules.json`。

## 案例库按条件触发

常规核算不读取 `calibration_cases.jsonl`。仅以下情况检索最多3个相似案例：用户提交实际物流反馈、当前SKU或数量冲突、结构无法可靠分类、估算明显数量级异常、正常档/保守档逻辑异常、用户明确要求校准。

案例状态：`validated` 可参考实际数值范围；`pending` 只能提醒检查SKU/折叠/压缩/嵌套，禁止反推尺寸或费用；`deprecated` 不参与判断。

## 两档语义

- **正常档：** 当前证据下最可能发生的普通代发包装。
- **保守档：** 物理合理范围内、成本略高的可发生场景。只调整不确定因素，不得机械放大全部三轴。

## 输出收口

利润核算：一句商品信息 + 两张固定表格 + 一句推算。
仅头程：一句商品信息 + 一张固定表格 + 一句推算。

完整表头和行顺序由 `SKILL.md` 定义。禁止默认增加：临界点推导、历史案例引用段落、工作日志、额外推荐列、内部执行过程。

## 仅头程定义

"仅头程" = 不计算尾程/利润/活动预留，但必须展示：纯头程 + 固定服务费 = 总头程。

货代推荐按总头程比较。固定服务费属于头程成本组成部分。
