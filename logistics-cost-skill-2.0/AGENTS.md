# AGENTS.md — 物流成本核算 Skill v2.1

## 项目目标
电商单件跨境物流头程成本核算。Codex 读取商品图片 → 输出 AI JSON → Python 确定性计算。

## 任务分类

**开发任务：** 修改代码、规则、配置或文档 → 执行 Git 检查、必要验证和提交。

**日常核算：** 用户上传图片或要求计算 → 不检查 Git、不运行测试、不写报告、不生成文件。

## 模式（仅当前对话有效）

两种模式：1. 利润核算 / 2. 仅头程。

### 模式状态只存在于当前聊天对话中

仅以下情况视为"当前对话已选择模式"：用户明确回复 1 或 2、明确说"利润核算"或"仅头程"、在当前核算请求中明确指定模式。

### 新对话第一次核算

如果当前对话从未明确选择模式，最终回复必须严格只有：

```
请选择本次核算模式：

1. 利润核算
2. 仅头程
```

随后立即停止。此时禁止：识别图片、分析SKU、估算重量、读取包装规则、生成AI JSON、运行Python、输出商品信息或表格。

禁止出现："需要先确认模式"后继续计算、"沿用今日head_only"、"沿用上轮模式"、"按MEMORY偏好继续"、先计算再让选择。

### 同一对话新增商品

当前对话已选模式后，后续任何商品直接沿用，不再询问。用户说"切换到利润核算"或"切换到仅头程"时才切换。

### 禁止外部模式来源

不得从以下位置读取、推断或恢复模式：`local_user_preferences.json`、MEMORY.md、工作日志、上一个聊天窗口、历史输出、Git文件、模型长期记忆。四项利润参数仍可跨对话保存；核算模式不得保存。

## 缺失参数自动估算

这是一个估算工具。缺少物理参数不能阻断头程核算。

缺重量：根据图片/材质/结构估算净重，正常档用最可能值，保守档吸收不确定性。内部标记 `weight_source=ai_estimated, confidence=low`。

缺尺寸：根据可见比例和物理结构估算运输包装（先判断折叠/压缩/刚性轴），不得直接使用展示外廓。

缺数量：默认 `quantity=1, quantity_source=assumed`。明确套装时按件数，不确定时用最可能SKU并降低置信度。

**仅以下情况允许向用户询问：** 图片无法识别任何有效商品、图片完全模糊、无法判断要核算哪个商品。普通重量/尺寸缺失不属于阻断条件。

**禁止弹窗：** 不得出现"请选择是否补充重量""请先填写再计算""核对参数表后重算"等。

## 最终结果必须在可见回复

思考区/过程区/工具区不算正式交付。所有用户需要查看的结果必须完整出现在最终可见回复中。

仅头程：1句商品信息 + 1张四行七列表格 + 1句推算。
利润核算：1句商品信息 + 第1张四行七列表格 + 1句默认参数 + 第2张四行六列表格 + 1句推算。

禁止最终回复出现：小结、项目符号总结、"当前模式"、"沿用上轮"、临界点公式、W=0.2kg推导、历史案例名称、AI JSON经验说明、调用次数、风险列表、"建议核对参数后重算"、"已记入MEMORY.md"。低置信度只在商品信息句中提一次。

## 禁止日常写MEMORY和文件

日常核算禁止：创建/修改MEMORY.md、写工作日志、修改AGENTS/SKILL/knowledge/、保存临时AI JSON/Markdown、修改examples/、提交Git。即使发现新经验也只用于当前结果，不自动固化。

## 四项参数（跨对话持久化）

仅持久化：`exchange_rate`、`tail_fee_usd`、`target_profit_rate_percent`、`activity_reserve_percent`。

保存于 `config/local_user_preferences.json`。用户修改任意一项时只更新该项。仅头程模式不读取这些参数参与输出，但不清空。

## 日常快速路径

```
确认当前SKU和数量
→ 一次图片理解
→ 选择一个最匹配的物理结构类型
→ 读取对应规则
→ 生成正常档与保守档
→ 运行一次Python确定性计算
→ 按固定Markdown格式输出
```

默认不得：扫描仓库、逐类比较全部规则、读取案例库、访问网页、执行Git、运行测试、保存AI JSON、生成Markdown/PDF/Excel、输出内部过程。

## 调用上限

每个商品默认最多：1次图片理解 + 1次结构规则匹配 + 1次Python计算。

仅异常检查命中时允许：重新生成包装方案1次 + 再运行Python计算1次。不得循环重试。

## 当前SKU优先

证据优先级：用户明确说明 > 当前高亮SKU/已选文字/数量 > 当前规格重量和尺寸 > validated案例 > 通用物理规则 > pending案例 > AI经验推测。

禁止用同页套包、其他颜色、宣传组合或历史套包覆盖当前单包。

## 通用物理包装原则

任何商品都必须先区分展示状态与运输状态，再判断刚性主体、可折部件、可拆附件、压缩、嵌套和局部保护；不得把展示总尺寸直接作为运输包装尺寸。

详细分类见 `SKILL.md` 和 `knowledge/physical_packaging_rules.json`。

## 案例库按条件触发

常规核算不读取 `calibration_cases.jsonl`。仅以下情况检索最多3个相似案例：用户提交实际物流反馈、当前SKU或数量冲突、结构无法可靠分类、估算明显数量级异常、正常档/保守档逻辑异常、用户明确要求校准。

案例状态：`validated` 可参考实际数值范围；`pending` 只能提醒检查SKU/折叠/压缩/嵌套，禁止反推尺寸或费用；`deprecated` 不参与判断。

## 两档语义

- **正常档：** 当前证据下最可能发生的普通代发包装。
- **保守档：** 物理合理范围内、成本略高的可发生场景。只调整不确定因素，不得机械放大全部三轴。

## 输出收口

利润核算：一句商品信息 + 两张固定表格 + 一句推算。
仅头程：一句商品信息 + 一张固定表格 + 一句推算。

完整表头和行顺序由 `SKILL.md` 定义。禁止默认增加：临界点推导、历史案例引用段落、工作日志、额外推荐列、内部执行过程。

## 仅头程定义

"仅头程" = 不计算尾程/利润/活动预留，但必须展示：纯头程 + 固定服务费 = 总头程。

货代推荐按总头程比较。固定服务费属于头程成本组成部分。
