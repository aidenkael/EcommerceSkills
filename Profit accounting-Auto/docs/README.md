# 微智能商品利润管理 v0.1

本项目是一个本地桌面端商品利润测算与历史管理工具。它不负责商品采集、ERP 同步或正式财务记账。

## 运行环境

- Python 3.10+
- 运行时仅使用标准库：`tkinter`、`sqlite3`、`json`、`uuid`、`datetime`
- 自动测试使用 `pytest>=7.0.0`

启动：

```powershell
cd "E:\EcommerceSkills\Profit accounting-Auto"
python app.py
```

首次启动会创建 `data/profit_accounting.db`。

Windows 打包：

```text
双击 build_windows.bat
```

生成文件为 `dist\ProfitAccountingAuto.exe`。打包版的数据不会写入临时解压目录，而是固定保存在 `%LOCALAPPDATA%\ProfitAccountingAuto\profit_accounting.db`。

## 功能

### 新商品测算

可录入：

- 商品名称、采购成本、发往中转仓运费
- 裸件重量（g）和尺寸（裸件尺寸只记录）
- 包装后重量（g）和尺寸
- 不限数量的动态货代（显示名称和规则可改，内部 UUID 稳定）
- 尾程费用
- SHEIN 二次核价（美元）、人民币/美元售价
- 目标净利率、推广预留比例和备注

结果区显示体积重、计费重量、头程、总物流成本、总成本、净利润、净利率、建议售价和折合美元。

### 历史记录

- 按名称或商品 ID 搜索
- 打开并继续编辑商品
- 删除商品及其首次快照
- 优先展示最近一次保存的计算结果
- 成本数据不完整时显示“数据不足”，不会将缺失成本当作零

### 设置

菜单栏的“汇率与费用设置”可修改：

- 汇率：`1 USD = ? RMB`
- 默认尾程费用
- 动态货代规则

设置分为全局设置与动态货代管理。货代可不限数量新增，使用不可修改的 UUID 作为内部标识；每个货代独立维护显示名称、头程单价、固定服务费、体积重除数和启用状态。货代列表支持滚动。未被历史商品或快照引用的货代可永久删除；被引用的货代会停用并归档，以保留历史关联。归档货代可恢复，恢复后默认保持停用，需人工确认规则并重新启用。新商品下拉框只显示启用且未归档的货代。

“设置”菜单还提供整库备份与恢复。备份包含商品、首次快照、当前计算结果、货代和全局设置。恢复前会验证备份、迁移旧版本，并自动保留一份当前数据库的 `before_restore` 安全备份；恢复失败时不替换当前数据。

## 当前业务规则

| 项目 | 货代一（默认深圳） | 货代二（默认义乌） |
|---|---:|---:|
| 头程单价 | 80 元/kg | 100 元/kg |
| 固定服务费 | 10 元 | 6 元 |

默认参数：

- 每个货代自己的体积重除数（首次默认 8000）
- 默认尾程费用：40 元
- 默认汇率：7.20

这些值保存在数据库配置和货代规则表中。历史商品使用保存时的规则；只有显式选择“用当前规则重算”后，才切换到当前规则。

## 计算公式

| 结果 | 公式 |
|---|---|
| 体积重 | 包装长 × 包装宽 × 包装高 ÷ 保存的体积重除数 |
| 实际重量 | 包装后重量(g) ÷ 1000 |
| 计费重量 | `max(实际重量kg, 体积重)` |
| 头程费用 | 计费重量 × 保存的货代头程单价 |
| 总物流成本 | 头程 + 固定服务费 + 尾程 |
| 总成本 | 商品成本 + 发往中转仓运费 + 总物流成本 |
| 净利润 | 售价 − 总成本 − 售价 × 推广预留比例 |
| 净利率 | 净利润 ÷ 售价 × 100% |
| 建议售价 | 总成本 ÷ (1 − 目标净利率 − 推广预留比例) |
| 人民币转美元 | 人民币 ÷ 汇率 |

任一必要成本缺失时，总物流成本、总成本和利润返回缺失；界面可以显示已知成本下限，但不会据此计算利润。

金额和比率在数据库中保留 Python 浮点计算结果，界面统一显示两位小数。目前没有按平台结算规则执行逐项分币舍入。

## 保存状态与还原

系统区分两类状态：

1. **当前保存状态**：商品最近一次保存的输入、规则和计算结果；下次打开时使用。
2. **首次快照**：商品第一次保存时的输入、规则和计算结果；保持不可变，仅供“还原”按钮使用。

新商品的当前状态和首次快照在同一个数据库事务内创建。已有商品再次保存时，只更新当前状态，不改写首次快照。

## 数据库

源码运行数据库：`data/profit_accounting.db`

打包运行数据库：`%LOCALAPPDATA%\ProfitAccountingAuto\profit_accounting.db`

主要表：

- `products`：当前商品输入、当前规则快照、当前计算结果
- `product_snapshots`：首次不可变快照
- `route_config`：动态货代规则（UUID、显示名称、费率、服务费、体积重除数、启用/归档状态和时间戳）
- `config`：汇率和默认尾程
- `schema_version`：数据库结构版本
- `business_rule_version`：业务规则版本

当前 Schema 版本为 5。旧重量数据不自动换算：迁移后标记为 `legacy_unknown`，打开时需核对克数并重新保存为 `g_v1` 后才允许按当前规则重算。旧商品仍可显示冻结结果。重量输入均为 g，内部以 g÷1000 换算 kg 计费；SHEIN 二次核价为美元参考值，不参与人民币利润公式。保存的当前规则和首次快照均保留 `route_id` 与当时的显示名称，因此后续改名不会篡改历史显示或冻结结果。

## 测试

```powershell
python -m pip install -r requirements.txt
python -m pytest tests -q
```

测试覆盖计算公式、输入校验、动态货代规则、归档/删除/恢复、真实 v4 迁移、手工备份/安全恢复、打包数据目录、严格缺失传播、数据库 CRUD、首次快照、当前状态、迁移回滚、规则切换保存和历史结果冻结。

## 已知边界

- 尚未接入平台手续费、税费、退款率或不同平台的结算舍入规则。
- 尚未实现批量导入、报表导出、图片管理或 ERP/API 对接。
- 自动测试覆盖业务与持久化路径，但仍需进行真实 GUI 人工点击验收。
- v2 时代如果记录已经出现“当前商品与首次规则互相冲突”，系统无法在没有外部证据时推断真实历史费率，迁移后应人工复核。
