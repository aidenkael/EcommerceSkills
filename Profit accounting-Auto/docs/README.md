# 微智能商品利润管理 v0.1

本项目是一个本地桌面端商品利润测算与历史管理工具。它不负责商品采集、ERP 同步或正式财务记账。

## 运行环境

- Python 3.10+
- 运行时仅使用标准库：`tkinter`、`sqlite3`、`json`、`uuid`、`datetime`
- 自动测试使用 `pytest>=7.0.0`

启动：

```powershell
cd "E:\EcommerceSkills\Profit accounting-Auto"
python app.py
```

首次启动会创建 `data/profit_accounting.db`。

## 功能

### 新商品测算

可录入：

- 商品名称、采购成本、发往中转仓运费
- 裸件重量（g）和尺寸（裸件尺寸只记录）
- 包装后重量（g）和尺寸
- 两个可配置货代槽位（显示名称可改，内部键稳定）
- 尾程费用
- SHEIN 二次核价（美元）、人民币/美元售价
- 目标净利率、推广预留比例和备注

结果区显示体积重、计费重量、头程、总物流成本、总成本、净利润、净利率、建议售价和折合美元。

### 历史记录

- 按名称或商品 ID 搜索
- 打开并继续编辑商品
- 删除商品及其首次快照
- 优先展示最近一次保存的计算结果
- 成本数据不完整时显示“数据不足”，不会将缺失成本当作零

### 设置

菜单栏的“汇率与费用设置”仅修改：

- 汇率：`1 USD = ? RMB`
- 默认尾程费用

设置分为全局设置与两个货代区域。每个货代独立维护显示名称、头程单价、固定服务费、体积重除数和启用状态；不支持新增或删除货代。

## 当前业务规则

| 项目 | 货代一（默认深圳） | 货代二（默认义乌） |
|---|---:|---:|
| 头程单价 | 80 元/kg | 100 元/kg |
| 固定服务费 | 10 元 | 6 元 |

默认参数：

- 每个货代自己的体积重除数（首次默认 8000）
- 默认尾程费用：40 元
- 默认汇率：7.20

这些值保存在数据库配置和货代规则表中。历史商品使用保存时的规则；只有显式选择“用当前规则重算”后，才切换到当前规则。

## 计算公式

| 结果 | 公式 |
|---|---|
| 体积重 | 包装长 × 包装宽 × 包装高 ÷ 保存的体积重除数 |
| 实际重量 | 包装后重量(g) ÷ 1000 |
| 计费重量 | `max(实际重量kg, 体积重)` |
| 头程费用 | 计费重量 × 保存的货代头程单价 |
| 总物流成本 | 头程 + 固定服务费 + 尾程 |
| 总成本 | 商品成本 + 发往中转仓运费 + 总物流成本 |
| 净利润 | 售价 − 总成本 − 售价 × 推广预留比例 |
| 净利率 | 净利润 ÷ 售价 × 100% |
| 建议售价 | 总成本 ÷ (1 − 目标净利率 − 推广预留比例) |
| 人民币转美元 | 人民币 ÷ 汇率 |

任一必要成本缺失时，总物流成本、总成本和利润返回缺失；界面可以显示已知成本下限，但不会据此计算利润。

金额和比率在数据库中保留 Python 浮点计算结果，界面统一显示两位小数。目前没有按平台结算规则执行逐项分币舍入。

## 保存状态与还原

系统区分两类状态：

1. **当前保存状态**：商品最近一次保存的输入、规则和计算结果；下次打开时使用。
2. **首次快照**：商品第一次保存时的输入、规则和计算结果；保持不可变，仅供“还原”按钮使用。

新商品的当前状态和首次快照在同一个数据库事务内创建。已有商品再次保存时，只更新当前状态，不改写首次快照。

## 数据库

数据库：`data/profit_accounting.db`

主要表：

- `products`：当前商品输入、当前规则快照、当前计算结果
- `product_snapshots`：首次不可变快照
- `route_config`：深圳/义乌货代费率
- `config`：汇率和默认尾程
- `schema_version`：数据库结构版本
- `business_rule_version`：业务规则版本

当前 Schema 版本为 4。旧重量数据不自动换算：迁移后标记为 `legacy_unknown`，打开时需核对克数并重新保存为 `g_v1` 后才允许按当前规则重算。旧商品仍可显示冻结结果。

## 测试

```powershell
python -m pip install -r requirements.txt
python -m pytest tests -q
```

测试覆盖计算公式、输入校验、双货代规则、严格缺失传播、数据库 CRUD、首次快照、当前状态、迁移回滚、规则切换保存和历史结果冻结。

## 已知边界

- 尚未接入平台手续费、税费、退款率或不同平台的结算舍入规则。
- 尚未实现批量导入、报表导出、图片管理或 ERP/API 对接。
- 自动测试覆盖业务与持久化路径，但仍需进行真实 GUI 人工点击验收。
- v2 时代如果记录已经出现“当前商品与首次规则互相冲突”，系统无法在没有外部证据时推断真实历史费率，迁移后应人工复核。
